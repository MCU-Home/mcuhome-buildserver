# Development install:
#
#     python3 -m venv .venv && . .venv/bin/activate
#     pip install -r requirements-dev.txt
#
# This repository no longer needs a sibling checkout to run. It used to
# install `-e ../mcuhome` and `-e ../cli`, because the build server
# spawned the `mcuhome` command as its builder and imported the library
# for the version it was about to spawn; both went with the job
# protocol. The build server is an orchestrator and is never itself the
# build environment, so there is no builder to install alongside it.
#
# The dependency that will come back is `mcuhome-model` (ADR 0020
# decision 1), for the frozen context-ID rule of ADR 0018 §6. It arrives
# with the context path, and when it does it belongs in pyproject.toml
# as a real dependency rather than here.
#
# There is deliberately no `mcuhome-dashboard` here, and no sibling
# checkout of it either: the build server depends on the build-container
# contract and on nothing else (ADR 0017 decision 3, dashboard ADR 0012).
# The frame envelope the two products share is pinned by the contract,
# not by importing one product into the other's test run.
-e .[dev]
