# Development install:
#
#     python3 -m venv .venv && . .venv/bin/activate
#     pip install -r requirements-dev.txt
#
# The `mcuhome` builder is spawned as a subprocess (see
# mcuhome_buildserver/builder.py); the library is imported only for its
# version constants. The command itself ships in its own thin repo
# (github.com/mcu-home/cli) since the CLI extraction. Neither package is
# published yet, so both come from sibling checkouts in the west
# workspace:
#
#     <workspace>/mcuhome/        the builder library
#     <workspace>/cli/            the `mcuhome` command
#     <workspace>/build-server/   this repository
#
# There is deliberately no `mcuhome-dashboard` here: the build server is
# a separate product and must be installable without it (dashboard ADR
# 0003). Installing the sibling checkout's backend additionally
# (`pip install -e ../dashboard/backend`) enables the frame-vocabulary
# cross-check in tests/test_protocol.py, which otherwise skips.
-e ../mcuhome
-e ../cli
-e .[dev]
